# Evervale — Design agreements / prototype 05

- Login only before account session. New accounts use ID/password; Supabase aliases IDs internally, no personal email required. Requires Confirm email disabled. Existing email accounts remain accessible via original login in ID field.
- Main menu: new game, load, database, settings. New character: nine original races, eight primary classes. No half races. Human, elf, dwarf, halfling, orc, tiefling, dragonborn, gnome, fae. Warrior, rogue, mage, priest, ranger, buffer, alchemist, knight.
- STR DEX CON INT WIS CHA. Fixed 1 passive + 2 active per class. Names reused where available; activity effects and race traits in this patch are provisional balance, not final approved combat designs.
- Imported all 112 skill, 59 spell, 36 proficiency presets from dnd-dm-game-v20_4-no-ai.jsx. Original fields retained in dist/content.js. Import does not mean all mechanics are implemented. Supported activity skills use explicit shared prototype effects shown in UI. Others are retained for later integration.
- Discovery is distinct from learning. Only discovered records appear in player database. Basic/deep information comes from appraisal or teachers/books. Rare eyes cannot be bought from ordinary learn UI. Learning checks every declared level/stat/proficiency/class condition.
- Kishirika remains temporarily. 5% gate per completed eligible activity, at least 30 activity turns since last encounter. 9 equally weighted unowned eyes, 20-coin food example cost. Cost deducted only with actual grant. Event pauses activity batches. Character identity is separated from generic eye pool/rules for replacement later.
- Time advances by activities only, never wall clock. Human lifespan randomized 80–100; other race lifespans are provisional values. Activities, plan safeguards, save revision conflicts retained.
- Saves isolated by Supabase user ID. Existing v2 cloud/export saves migrate without losing activity progress, require choosing character identity. Legacy shared local v2 remains untouched; export/import explicitly to claim it. Local backup made before replacement. Cloud existing save never overwritten on login.
- Deferred: secondary/special classes, offspring, mixed lineage, full combat adapters, complete original NPC redesign, generated map background.

Validation: run node rules.test.cjs and node cloud.test.cjs. Browser QA separately.

Prototype 07 — full legacy database/forms migration:

- 504 original presets: NPC 40, monster 35, weapon 31, armor 25, accessory 50, helmet 25, boots 25, spell 59, skill 112, proficiency 36, item 27, recipe 5, dropItem 34. The 2 activity-alchemist records remain, total 506.

IDs and canonical names remain stable for reference compatibility; displayed names are editable.
- All original fields, plus legacy extra preset fields not in the schema, survive edits and exports. Form save uses original types and preserves missing-schema data. JSON is optional; edits must be explicitly applied back into the form.
- Paged catalog (24 records/page) keeps mobile editing responsive. Full main-menu catalog is separate from character discoveries. New non-skill categories are not added to the activity discovery pool.
- Cloud-save load now restores validated editor overrides. Editing cannot activate systems that the current activity prototype has not implemented: combat, inventory/equipment, shops, crafting, NPC recruitment and many passive effects remain data only. UI explicitly marks this.

Prototype 08 — independent Supabase image/content sync before character creation:
- Uploaded images remain Base64 data URLs. Persisting any library edit now emits an independent content event rather than a gameplay save, and uploads automatically without a character.
- Uses the existing RLS-protected evervale_saves row. contentLibrary is a logically independent JSON section; content-only updates copy the current remote row and change only the library section plus its legacy contentEdits mirror. No table migration or admin key is required. Library-only rows contain a valid fresh v3 envelope with character:null.
- On login, loads the remote library automatically without loading/replacing gameplay. Local unsent edits merge against a cached baseline. Three-way field-level merging accepts disjoint changes and explicitly stops on same-field conflicts. Users may pull/push only the library after confirmation.
- Revision CAS and bounded retries preserve concurrent gameplay changes. A library write advances the gameplay revision only when its prior revision was known locally, otherwise stale gameplay autosync is disabled. Gameplay writes preserve the independently synced library.
- Dedicated status, retry, online recovery and unload/logout pending guards. Edits made during an upload remain pending. Local and JSON backups remain supported; importing save-carried edits also queues a library sync.
- Validation: library-merge.test.cjs, cloud.test.cjs and rules.test.cjs passed. image-cloud.test.cjs uploads an actual PNG, checks Base64, writes without a character, restores from a fresh browser context, preserves existing gold/character/history and retries after offline. full-schema.test.cjs still passed all 205 fields. Browser cloud transport is mocked; no user credentials or real player saves were used in tests.

Prototype 09 — image maps, place pins and nested maps:
- Added main-menu/world tools, settings and in-game map editor entrypoints. Upload background images or use image URLs. Uploads accept raster source images up to 10 MB and resize to WebP (1800px longest side); custom place icon images resize to 96px. Existing 2 MB aggregate library limit is shown in the UI.
- Map definitions live under the reserved worldMap:main library key with strict versioned validation. Supports 1–20 maps, 0–80 locations per map, root map selection, percent positions, descriptions, emoji/custom-image icons, visibility, activity lists, and explicit child-map destinations. No arbitrary code/actions in definitions.
- Editor adds/removes maps and places, drags pins with pointer capture, moves selected pins by clicking/tapping the background or editing numeric X/Y, links places to child maps, and guards unsaved changes. Invalid/dangling links, duplicate IDs, unsafe image schemes and invalid action/coordinate values are rejected. Deleting a map clears incoming links.
- Gameplay uses uploaded images at their native aspect ratio without crop. Icons enter a child map or a location panel with configured activity buttons. Back/root navigation is provided. Viewing/travel navigation does not advance time; activities use the existing safeguards, durations and progression. Current map/place navigation is part of the character snapshot.
- Map images and definitions share the independent library sync from prototype 08, work before creating a character, auto-load on another device, and accompany JSON exports. Existing gameplay is preserved. Remote library changes refresh maps and pending drafts remain protected.
- Verified map-data.test.cjs, maps.test.cjs, browser.test.cjs, image-cloud.test.cjs, full-schema.test.cjs, rules.test.cjs, cloud.test.cjs and library-merge.test.cjs. Map browser test covers real image/custom-icon upload, drag percent coordinates, root/child maps, inn activity, activity-only time, cross-browser restore before character creation, coexisting map/game saves, mobile layout and unsaved guard. Supabase transport is mocked for browser tests; no real player data used.

Prototype 11 — character art slots:
- Added optional icon, portrait and combat-image inputs to character creation, each with file upload, URL, preview and clear controls. Original raster uploads up to 10 MB are resized/encoded as transparent-capable WebP; icon/portrait/combat longest sides are 128/640/1200 px with bounded stored payloads. Full portrait/combat art is contained rather than cropped.
- Images live in character.images and travel with local saves, cloud saves and JSON export/import. Legacy characters without images remain valid. Save validation rejects unsafe URL/data schemes, invalid types and oversized image values. Full-save import limit increased to 6 MB for save-carried images and library data.
- Icon and portrait render in the character panel. Existing characters can add/edit all three images in a dialog without recreating a character or changing progression. Combat image is retained and previewed for the future combat scene; no combat runtime is implied.
- Async image processing disables confirmation until ready and ignores stale completions on reset/cancel/account change. Canceling existing-character edits leaves the saved images unchanged. Failed local save caching still emits the cloud-save event so storage quota failure does not suppress cloud synchronization.
- Validation: character-art-data.test.cjs, character-art.test.cjs, browser.test.cjs, rules.test.cjs and cloud.test.cjs passed. Browser art test uploads all three images, checks previews/mobile layout, saves/restores via mocked Supabase in a fresh browser, edits/clears/cancels without changing progression, rejects invalid files and reloads local images. No real player credentials/saves used.

Prototype 12 — grid scene workshop and movement playtest:
- Added a canvas grid editor accessible before character creation and from the game map. Thirty scenes, three biome categories (meadow, forest, cave), 6–24 cells on each axis, blank/copy/delete/resize/filter tools, brush painting with pointer capture, keyboard selection/painting, undo/redo, per-cell elevation and climb access.
- Terrain data includes ground/grass/water, bushes/trees/rocks/walls, height 0–4, climb flags, player/enemy spawns and optional monster IDs from the existing catalog. Stable, strictly validated scene data lives in battleScenes:main in the independent content library and accompanies existing library/cloud/export flows. Shared library capacity remains 2 MB. Incomplete scenes can be saved; blocked, missing or disconnected spawns prevent playtesting.
- Deterministic seeded generation per biome creates three spawn points per side and a guaranteed connecting route, plus accessible tree/cliff examples. Fresh random seed and repeat-from-seed actions, guarded replacement, undo support.
- Separate pure movement rules and canvas view. Four-direction weighted pathfinding, occupancy, 6 movement points/unit/turn, stepwise traversal, elevation costs, climbing steep faces only where enabled, and explicit tree base/perch states with ascent/descent. Movement playtest can select each player token and reset/advance turn. Campaign time/progression never changes.
- This is a scene authoring and traversal sandbox, not a finished combat system: enemy tokens stay at their spawns; attacks, AI, skills, cover/line-of-sight and automatic encounter selection are not implemented. Existing combat character images remain separate; placeholder tokens used as art work was deferred by user.
- Unsaved navigation/logout/page-close guards; account reset cancels animation; cloud changes during drafts/testing are retained for explicit reconciliation; save status and retry use existing Supabase library sync.
- Tested battle-data.test.cjs (108 deterministic generated layouts, validation, connectivity, occupancy, tree/cliff movement costs), battle-editor.test.cjs (real browser painting/undo, save/second-browser restore, climbing, MP, campaign isolation, seed generation, responsive layout and in-game access), rules, cloud, library-merge, maps, character-art, full-schema tests. Supabase transport mocked; no real account saves modified. Desktop/mobile screenshots reviewed and panel contrast corrected.

Prototype 13 — isometric 2.5D scene view and explicit map dimensions:
- Replaced the square overhead renderer with a standalone canvas isometric diorama view: elevated tile side faces, cliff strata and climb ladders, shaded trees/pines, bushes, rocks, cave stalagmites, textured grass/soil/water, biome palettes, cast shadows, spawn flags and test pawns. Existing scene definitions and movement/climbing rules remain compatible; no migration or art dependency.
- Added a persistent camera viewport with zoom buttons/wheel, pan brush/middle drag/Space drag, fit-to-view, grid visibility and transparent-tree toggles. Inverse isometric hit testing accounts for elevation and camera transforms. Mouse/touch painting and keyboard editing retained. View/camera data is transient and never changes scene saves or campaign state.
- Map dimensions promoted into a prominent card: custom width/length independently 6–40, presets 8x8, 16x12, 24x24, 32x24, 40x40, current cell count, explicit apply, crop warning and resize preserving overlapping cells. Blank creation and generation respect chosen dimensions. Scene validation expanded to 40 per axis; JSON-safety array cap expanded to 1600 for a 40x40 tile array. Existing aggregate 2 MB library limit still enforced and explained.
- Verified battle-data.test.cjs across 144 seeded generated maps up to 40x40; battle-view.test.cjs covers fitted bounds and pixel picking for small/rectangular/large scenes, elevated tiles and desktop/mobile. Updated battle-editor.test.cjs passes all prior movement/climbing/cloud/campaign-isolation flows with isometric coordinates. battle-isometric.test.cjs tests 40x40 editing/cloud roundtrip, presets/custom sizes, zoom/pan picking, invalid dimensions, resizing then generation, mobile overflow and view toggles. Supabase transport mocked. Three biome screenshots and mobile layout visually reviewed.
